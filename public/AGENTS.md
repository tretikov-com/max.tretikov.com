## Progress

Biology, let alone human biology, is too complex for any human to truly comprehend. There is too much data, too many moving parts. Machine learning is the perfect tool for this, a way to predict outcomes, synthesize vast data, and *understand* biology. My ultimate goal right now is to build a system that can use AI to analyze and pilot one human body: an RF-to-RNA (and vice versa) enzyme. It would have nanoradio antennas and would be able to turn a digital signal into mRNA fragments, which can screen for cell with a riboregulator sequence looking for spatial transcriptomic sequences; and would be able to transmit mRNA fragments with a header sequence given by that riboregulated mRNA. We can use the whole field of synthetic biology to achieve complex multivariable calculation within the cell. But there are so many hurdles to this. Primarily: we can't make new to nature enzymes that are this freaky because there's a data dearth in biology. There are too many experiments, of great expense to run. So what do we do? We make synthetic data. We figure out how to simulate, with haste, at scale, precisely. This, combined with robotic automated labs, I believe will give us enough data to make my RfNA enzymes. From there, we get a SHITLOAD of data from an in-vivo living cell, rather than current expensive methods of lysing a cell, extracting and sequencing RNA, in an apoptosed dead state. So this is where you come in, to help write the software we'll need for this. But how?

## Philosophy

ALWAYS start with the minimum viable product. YAGNI, only build things we need right now. That being said, I prioritize elegance and abstraction. DRY. Always make a system extensible and modular, just not overengineered. 

When you remove something, you don't need to write that you removed it, or add tests to ensure it stays removed. You just remove it. You don't need to keep anything backwards compatible with things you wrote in the past. Move forwards, eternally. Imagine that what you're writing is being read for the first time by someone with no context. Only keep that kind of info in your own documents (only read by machine), if you absolutely must (don't forget you have a biiiig context window).
